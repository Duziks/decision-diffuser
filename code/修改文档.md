# Decision Diffuser 动态 Shape 改造说明

## 1. 改造目标


- 使用 `SHAPE_LIST` 配置多组 `batch_size,seq_len`。
- 使用 `--enable_dynamic_compile None` 启用 PyTorch 自动动态编译。
- 第一次运行时完成一次编译，后续不同 Shape 复用同一份动态图。
- 运行过程中自动打印 compile 次数和每次处理的输入 Shape。
- 保留原有固定 Shape、训练和 MuJoCo 评估流程。

动态 Shape 的核心调用链如下：

```text
analysis/launch.sh + analysis/parser.py
                    |
                    v
scripts/evaluate_inv_parallel.py
                    |
                    v
diffuser/utils/training.py
                    |
                    v
diffuser/models/diffusion.py
```

## 2. 运行顺序

必须先运行 `train` 模式生成权重，再运行 `eval` 模式加载权重并进行动态 Shape 测试。

### 2.1 进入目录

```bash
cd /path/to/rec_model_zoo_pytorch/decisison-diffuser/decision-diffuser/code/analysis
```

### 2.2 第一步：运行 train 生成权重

先将 `analysis/launch.sh` 中的运行模式和 Shape 配置设为：

```bash
PATTERN=train
export SHAPE_LIST=""
```

训练阶段不需要轮换动态 Shape。执行：

```bash
bash launch.sh
```

训练完成后确认权重已经生成。当前启动参数使用：

```bash
--bucket=../weights
--n_diffusion_steps=10
```

对应评估权重通常为：

```text
../weights/checkpoint10/state.pt
```

如果修改了 `n_diffusion_steps` 或训练输出目录，eval 阶段必须使用相同配置和对应的
`state.pt`，不能继续加载 `checkpoint10`。

### 2.3 第二步：运行 eval 测试动态 Shape

确认权重存在后，将 `analysis/launch.sh` 改为：

```bash
PATTERN=eval
export SHAPE_LIST="8,96;16,100;32,104"
```

动态编译相关参数保持为：

```bash
--compile=true \
--graph=false \
--dynamic_batch=false \
--enable_dynamic_compile None \
```

然后执行：

```bash
bash launch.sh
```

`SHAPE_LIST` 中每项的格式为 `batch_size,seq_len`，多个 Shape 使用分号分隔。例如：

```text
8,96       -> batch_size=8,  seq_len=96
16,100     -> batch_size=16, seq_len=100
32,104     -> batch_size=32, seq_len=104
```

`None` 必须保留首字母大写，解析器会将字符串 `None` 转换为 Python 的 `None`，并传给：

```python
torch.compile(..., dynamic=None)
```

## 3. 运行日志

compile 次数和输入 size 已经默认自动打印，不需要额外设置 `TORCH_LOGS`，也不需要单独执行
重编译检查命令。

运行时会看到类似输出：

```text
[ utils/training ] torch.compile: enabled=True, dynamic=None, graph=False
[compile 1] start
[warmup 0] batch_size=8, seq_len=96, input_size=(8, 96, 11)
[compile 1] end
[warmup 1] batch_size=16, seq_len=100, input_size=(16, 100, 11)
[iter 0] batch_size=32, seq_len=104, input_size=(32, 104, 11)
```

判断标准：

- 日志持续轮换显示 `SHAPE_LIST` 中配置的 Shape。
- 整个 warmup 和正式迭代期间只出现一次 `[compile 1] start/end`。
- 如果出现 `[compile 2]` 或更大的编号，说明发生了重新编译，应检查新的 Shape、数据相关分支或 Graph Break。

## 4. 全部仓库文件改动

本次 commit 共涉及 18 个仓库文件。它们分为动态 Shape 核心改造、MuJoCo 兼容修复和文档三类。

### 4.1 动态 Shape 核心改造

#### `code/analysis/launch.sh`

- 增加 `SHAPE_LIST` 环境变量，格式与 `behaviour_and_multi_task/launch.sh` 保持一致。
- 增加 `--dynamic_batch` 和 `--enable_dynamic_compile` 启动参数。
- 保留 `--compile`、`--graph` 等原有编译开关。
- 设置 `PYTHONUNBUFFERED=1`，让 input size 和 compile 回调日志实时输出。
- 使用 `PATTERN=train`/`PATTERN=eval` 切换训练和评估流程。

#### `code/analysis/parser.py`

- 增加 `--dynamic_batch` 参数。
- 增加 `--enable_dynamic_compile` 参数。
- 支持将命令行字符串 `None` 转换为 Python 的 `None`。
- 参数名称和行为与公共模型启动方式保持一致。

#### `code/diffuser/utils/training.py`

这是动态 Shape 改造的主要文件，包含以下改动：

- 从 `SHAPE_LIST` 解析多组 `(batch_size, seq_len)`。
- 增加 `_next_shape()`，在 warmup 和正式迭代中循环切换 Shape。
- 根据当前 Shape 生成随机 state、conditions、returns、`x` 和 noise 输入。
- 递归处理字典、列表和 Tensor，对 batch 维和 seq_len 维调用
  `torch._dynamo.mark_dynamic`。
- 只在第一组输入上执行动态维度标记。
- 将 `enable_dynamic_compile` 原样传给 `torch.compile(dynamic=...)`。
- 注册 `torch._dynamo.on_compile_start`/`on_compile_end` 回调，自动打印编译编号。
- 自动打印 warmup 和正式迭代实际处理的 `batch_size`、`seq_len` 和 `input_size`。
- 调用 `conditional_sample(..., verbose=False)`，避免采样循环中的 Python 进度对象进入编译图。
- 补充 `Profiler` 和 `output_report` 导入，并修复 profiler 类名被局部变量遮蔽的问题。
- 性能报告传入实际的 `n_diffusion_steps`。

#### `code/diffuser/models/diffusion.py`

这是保证扩散采样能够完整编译的另一个核心文件：

- `GaussianInvDynDiffusion` 的采样路径支持外部传入 `x` 和 noise。
- 外部输入由测试代码按当前 batch size 和 seq_len 构造。
- `verbose=False` 时不再实例化 `utils.Silent()`。
- 移除非 verbose 路径中的 `progress.update()` 和 `progress.close()` 调用。
- 同步清理 `GaussianDiffusion` 和 grad sampling 路径中的进度对象交互。
- 减少扩散循环内的 Python Graph Break，使多步采样能够作为完整图捕获。

#### `code/scripts/evaluate_inv_parallel.py`

- `eval` 模式检测到动态 Shape 配置后，进入生成输入的性能测试路径。
- 动态测试不依赖实时 MuJoCo rollout，便于稳定验证多组 Shape 是否复用同一编译图。
- 未启用动态 Shape 时继续执行原来的 MuJoCo 并行评估。
- 性能报告使用实际 `n_diffusion_steps`。

#### `code/scripts/common.py`

- 提供 `Profiler` 和 `output_report` 公共实现。
- `output_report` 增加 `n_diffusion_steps` 参数。
- 将延迟计算中的硬编码 `/ 10` 改为按实际扩散步数计算。
- 避免将扩散步数调整为 20、200 等数值后报告结果不准确。

## 5. 最终检查

运行前检查：

```text
1. PyTorch 为支持 torch.compile 的 2.x 版本。
2. CUDA 可用。
3. 已先执行 train 并生成 state.pt。
4. eval 的 n_diffusion_steps 与权重目录一致。
5. 动态测试时 SHAPE_LIST 非空。
6. compile=true、graph=false、enable_dynamic_compile=None。
```

运行后检查：

```text
1. 日志显示多组不同 input_size。
2. 所有 Shape 均能完成 warmup 和正式迭代。
3. compile 回调只显示 compile 1。
4. 没有 TorchDynamo Graph Break 或 recompilation 报错。
5. 性能报告中的 batch size 和扩散步数与运行参数一致。
```
